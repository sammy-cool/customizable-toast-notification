Why not just use Sonner or react-toastify?

Honestly — if you're already all-in on React, they're excellent, and Sonner in particular is a great default. This library exists for the cases those don't cover.

Stack
You're not on React
Vue, Svelte, Angular, htmx, a plain multi-page app, an Electron shell, a browser extension. Every mainstream toast library assumes React. This one doesn't assume anything.
Content
Your toast message isn't always yours
Show user-generated content, API error text, or anything not fully trusted in a toast, and allowHtml is sanitized before it ever touches the DOM — DOMPurify if it's on the page, a verified-equivalent fallback if not.
Trust
You want to see the tests
129 real Playwright end-to-end tests across three browser engines, zero npm audit vulnerabilities, and a public CI/CD pipeline you can actually read. Not a claim — a repo.

Install

Two ways in. Same API either way.

npm / yarn
// install
npm install customizable-toast-notification

// use it anywhere — no provider, no wrapper component
import { createToast } from 'customizable-toast-notification';

createToast({ message: 'Saved successfully!', type: 'success' });
CDN — no build step at all
<script src="https://cdn.jsdelivr.net/npm/customizable-toast-notification/dist/index.umd.js"></script>
<script>
  customizableToast.createToast({ message: 'Hello!' });
</script>
